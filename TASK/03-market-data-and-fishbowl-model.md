# Task 03: Market Data And Fishbowl Model

## 目标

接入开源市场数据源，生成“主流宽基指数收盘价 + 20 日均线 + 鱼盆模型状态”的结构化模块，并插入日报。

## 前置澄清

这里的核心不是“把 AKShare 接上”，而是定义清楚：

- 跟踪哪些指数
- 20 日均线怎么计算
- 鱼盆模型的判定规则是什么
- 表格输出字段是什么
- 无法取数时怎么降级

## 本阶段交付

- 市场数据采集模块
- 指数指标计算模块
- 鱼盆模型规则模块
- markdown 表格输出
- 模块级单元测试

## 任务拆解

### 1. 明确数据源策略

建议做抽象，不把项目锁死在单一数据源上。

建议接口：

- `MarketDataProvider`
- `AkshareProvider`
- `FallbackMarketProvider`

### 2. 定义跟踪标的

建议第一版先做 4-6 个宽基指数，例如：

- 沪深 300
- 中证 500
- 中证 1000
- 上证指数
- 创业板指
- 恒生科技指数

最终名单以你的投资框架为准。

### 3. 定义计算字段

每个指数至少输出：

- 指数名称
- 交易日期
- 收盘价
- 20 日均线
- 偏离比例
- 鱼盆模型状态
- 备注

### 4. 固化鱼盆模型规则

这是本模块最关键的地方，必须写成明确规则，不要留在口头概念里。

至少要明确：

- 输入指标
- 判定阈值
- 状态枚举
- 状态解释文案

建议状态示例：

- `above_ma20`
- `near_ma20`
- `below_ma20`
- `data_missing`

### 5. 插入报告

建议在日报中增加单独模块：

- 标题：`市场数据观察`
- 内容：先表格，后简短分析

分析部分可以由规则模板生成，初期不依赖 LLM。

## 验收标准

- 在本地和 GitHub Actions 中都能生成指数表格
- 20 日均线计算正确
- 某个指数取数失败时，其它指数照常输出
- 鱼盆模型状态有稳定、可复现的判定逻辑

## 风险

- AKShare 在 GitHub Actions 环境的依赖和稳定性需要验证
- 不同数据源对指数命名和交易日处理可能不一致

## 建议优先级

P1，可与多领域新闻并行推进，但必须在基础层之后。
