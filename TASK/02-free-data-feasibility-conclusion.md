# Task 02 Free Data Feasibility Conclusion

## 结论摘要

这个项目在第一阶段可以建立在免费数据源之上，但前提不是“找到一个万能源”，而是“每类数据建立主源、备源、缓存和降级”。

总体判断：

- 科技、财经、时政新闻：可行
- 搜索热点补全：可行，但只能做辅助源
- 宏观指标：可行，但必须做口径治理
- 宽基指数行情：可行
- 未来会议与政策预告：可行，但必须把官方来源放在前面，豆包只能做研究补强

## 分类结论

### 新闻类

- 公开 RSS、官方博客、公告页足以支撑第一阶段接入验证。
- 真正的风险不是“拿不到新闻”，而是发布时间不统一、重复率高、时政质量波动大。
- 处理方式应是白名单源、统一时间解析、正文链接回填、去重规则前置。

### 搜索热点

- 搜索层能补到 RSS 覆盖不到的当日热点，但结果天然噪声更大。
- 因此搜索只做召回，不做最终事实确认。
- 搜索 provider 故障时，首页和推送都不应失败。

### 宏观指标

- 官方站点是最权威的主源，适合承担最终口径。
- AKShare 适合快速集成、样例开发和备源回填，但其部分接口依赖第三方页面，稳定性不能被默认假设。
- 所以宏观模块必须同时设计“官方源优先”和“上一期缓存回退”。

### 市场指数

- 宽基指数的日线级数据可先用 AKShare 验证。
- 交易所页面可作为备源，用于主源失效时回填基础收盘价。
- 20 日均线和鱼盆状态属于派生规则，应由服务层统一计算。

### 预告与研究

- 官方日历、部委公告、重要会议安排是高可信主源。
- 豆包 API 可以承担结构化研究和线索整理，但不能单独决定事件是否入库或展示。
- 每条豆包输出都必须附来源；无来源结果只能作为内部候选，不可直接上屏。
