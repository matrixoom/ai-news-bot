# Task 04: Events And Policy Outlook

## 目标

新增“未来一周 / 一个月 / 三个月 / 六个月”的热点会议、政策发布、政策落地预告模块。

## 本阶段交付

- 预告数据模型
- 预告采集接口
- 豆包 API provider 封装
- 时间窗口分类
- 预告 section 输出

## 核心原则

这类内容天然比新闻更容易出现幻觉，所以不能只让模型自由生成。

必须优先采用“检索 / 抽取 / 结构化归纳”流程，而不是单纯 prompt 让模型猜。

## 任务拆解

### 1. 先定义数据结构

建议 `UpcomingEvent` 包含：

- `title`
- `category`
- `region`
- `window`
- `expected_date`
- `confidence`
- `impact_summary`
- `source`
- `status`

### 2. 设计 provider 抽象

建议新增：

- `ForecastProvider`
- `DoubaoForecastProvider`

这样后面如果换源，不用重写业务逻辑。

### 3. 约束产出方式

豆包 API 输出必须是结构化 JSON，而不是自由文本。

建议模型任务：

- 输入给定时间窗口和关注主题
- 输出会议 / 政策 / 落地事项列表
- 每条都必须带来源或依据

### 4. 增加可信度分层

建议把预告按可信度分层：

- 高：有官方日历、正式公告、明确发布时间
- 中：多来源交叉印证，但尚未官宣
- 低：市场预期、行业传闻

默认主报告只展示高和中，低可信度只在可选附录展示。

### 5. 时间窗口组织方式

建议固定四档：

- 未来 7 天
- 未来 30 天
- 未来 90 天
- 未来 180 天

### 6. 输出结构

建议 section 结构：

- 热点会议预告
- 重点政策预告
- 重点政策落地观察点

## 验收标准

- 预告模块可独立开关
- 每条预告至少带一个来源依据
- 输出中有明确时间窗口和可信度
- 当外部 provider 不可用时，主日报仍能生成

## 风险

- 外部模型很容易输出未证实信息
- GitHub Actions 环境下接入新 provider 需要新增 secrets 和失败降级

## 建议优先级

P2，在新闻主链和市场数据稳定后再做。
