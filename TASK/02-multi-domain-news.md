# Task 02: Multi-Domain News Expansion

## 目标

把内容范围从“AI / 科技新闻”扩展到“科技 + 财经 + 时政”，并保持可配置、可裁剪。

## 本阶段交付

- 扩展配置结构，支持多内容域
- 为每个内容域配置 RSS 源和搜索查询模板
- 输出按域分组的报告结构
- 保持 AI 新闻仍然是核心版块，但不再是唯一版块

## 任务拆解

### 1. 重构配置结构

建议从当前平铺式 `news` 配置升级为：

```yaml
content:
  domains:
    - tech
    - finance
    - politics
  tech:
    enabled: true
    rss_sources: []
    search_queries: []
  finance:
    enabled: true
    rss_sources: []
    search_queries: []
  politics:
    enabled: true
    rss_sources: []
    search_queries: []
```

### 2. 建立领域源清单

每个领域都分两类：

- 优先级更高的官方 / 一级信源
- 覆盖面更广的媒体 / 聚合源

建议先做英文和中文两个优先语言，不要一开始把所有语言一起扩。

### 3. 定义领域级摘要策略

建议每个领域单独做“筛选 + 总结”，再统一装配，而不是把所有领域新闻混成一锅。

建议报告结构：

- 今日科技热点
- 今日财经热点
- 今日时政热点
- 市场数据观察
- 未来事件与政策预告

### 4. 建立领域级配额

避免某个领域把全部 token 吃完。

建议初始配额：

- 科技：8-12 条
- 财经：5-8 条
- 时政：5-8 条

### 5. 明确财经和时政范围边界

必须提前定义，否则后面摘要会漂。

财经建议覆盖：

- 指数、利率、汇率、商品、产业政策、重要财报、资金流向

时政建议覆盖：

- 国内外重大政策、监管、国际关系、产业影响明显的官方发布

## 验收标准

- 配置中可独立开关三个领域
- 生成报告时，每个领域都有单独 section
- 某个领域无数据时，不影响其他领域生成
- 领域间不会重复摘要同一事件

## 风险

- 财经和时政内容如果源选得太泛，会显著降低日报信噪比
- 多领域会增加 prompt 长度和模型成本

## 建议优先级

P1，紧跟基础层之后。
