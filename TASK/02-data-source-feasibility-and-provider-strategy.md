# Task 02: Data Source Feasibility And Provider Strategy

## 目标

优先解决“数据从哪里来、是否免费、是否足够稳定、如何抽象”的问题。最新需求的风险最大部分不在 UI，而在数据。

## 需要覆盖的数据类型

- 科技 / 财经 / 时政新闻
- 搜索热点
- 宏观经济指标
- 宽基指数行情
- 预告类信息

## 推荐数据源策略

### 1. 新闻 RSS 与公开媒体源

适合用于：

- 科技新闻
- 财经新闻
- 时政新闻

优点：

- 免费
- 易接入
- 适合 GitHub Actions 或服务端定时拉取

风险：

- 时效字段不统一
- 去重成本高
- 时政类源质量差异大

### 2. 搜索数据

可作为热点补全，不建议单独作为主来源。

建议策略：

- 先作为辅助源
- 搜索结果必须回填发布时间和原始链接
- 搜索命中不能直接入库，必须经过标准化和去重

### 3. AKShare

适合用于：

- A 股、港股、指数、宏观经济数据的第一批接入验证

优点：

- 免费
- Python 生态友好
- 覆盖中国市场较多

风险：

- 某些接口稳定性依赖第三方页面
- GitHub Actions 环境兼容性和频控需要验证
- 指标口径可能需要手工校验

### 4. 统计局 / 央行 / 官方公开页面

适合用于：

- CPI、PPI、GDP、杠杆率等宏观指标

优点：

- 权威
- 口径清晰

风险：

- 接口未必标准化
- 部分需要页面解析
- 更新频率不一致

### 5. 豆包 API

适合用于：

- 对会议、政策、落地事件做结构化研究和整理

不适合直接作为：

- 唯一事实源

正确使用方式：

- 检索增强后的结构化提取
- 带来源约束的 JSON 输出

## Provider 设计要求

每一类外部源都必须通过 provider 抽象暴露，不允许业务层直接写死依赖。

建议 provider 类型：

- `NewsProvider`
- `SearchProvider`
- `MarketDataProvider`
- `MacroDataProvider`
- `ResearchProvider`

## 本阶段交付

- 数据源矩阵
- provider 抽象清单
- 免费数据可行性结论
- 每类数据的主源 / 备源 / 降级方案

## 验收标准

- 每个模块至少有一个免费可行主源
- 每个关键数据类别都定义清楚失败降级策略
- 业务层不直接依赖第三方库实现细节

## 难点

- 免费数据可用，但不一定稳定
- 宏观和预告类数据更需要口径治理
