我本地已经有一份不复权的数据了，我不想再存两套前后复权的数据，该怎么办

```text
本地只存：
1. 不复权原始日线
2. 复权因子

使用时动态计算：
前复权价格 = 不复权价格 / 前复权因子
后复权价格 = 不复权价格 * 后复权因子
```

AKShare 的 `stock_zh_a_daily` 支持通过 `adjust="qfq-factor"` 和 `adjust="hfq-factor"` 返回复权因子；官方文档说明该接口的 `adjust` 参数包括不复权、前复权、后复权、后复权因子、前复权因子。([AKShare][1])

---

## 1. 复权因子返回格式

### 前复权因子

调用：

```python
import akshare as ak

qfq_factor_df = ak.stock_zh_a_daily(
    symbol="sz000002",
    adjust="qfq-factor"
)
print(qfq_factor_df)
```

AKShare 文档示例返回类似：

```text
         date            qfq_factor
0  2023-08-25    1.0000000000000000
1  2022-08-25    1.0517754291451000
2  2021-08-25    1.1168798473057000
3  2020-08-14    1.1810093745970000
4  2019-08-15    1.2245366427798000
```

也就是两列：

```text
date        复权因子生效日期
qfq_factor  前复权因子
```

官方文档中前复权因子示例就是 `date` + `qfq_factor` 这种结构。([AKShare][1])

---

### 后复权因子

调用：

```python
import akshare as ak

hfq_factor_df = ak.stock_zh_a_daily(
    symbol="sz000002",
    adjust="hfq-factor"
)
print(hfq_factor_df)
```

AKShare 文档示例返回类似：

```text
         date            hfq_factor
0  2023-08-25  169.1453113717332000
1  2022-08-25  160.8188465756604000
2  2021-08-25  151.4445011965874000
3  2020-08-14  143.2209726780933200
4  2019-08-15  138.1300530033661900
```

也就是两列：

```text
date        复权因子生效日期
hfq_factor  后复权因子
```

官方文档中后复权因子示例字段是 `date` + `hfq_factor`。([AKShare][1])

---

## 2. 注意：因子不是每天一条

复权因子通常不是每个交易日都有一行，而是在**除权除息、送转、分红等事件发生时变化**。

所以你拿到的数据类似：

```text
2023-08-25  1.0000
2022-08-25  1.0517
2021-08-25  1.1168
2020-08-14  1.1810
```

不是：

```text
2023-08-25
2023-08-24
2023-08-23
...
```

计算某个交易日的复权价格时，需要找到这个交易日对应的最近一条有效因子。

比如：

```text
2022-08-25 <= trade_date < 2023-08-25
```

这段时间使用：

```text
qfq_factor = 1.0517754291451000
hfq_factor = 160.8188465756604000
```

## 3. 你本地已有不复权数据，应该怎么做？

你的情况最适合这个方案：

```text
market_stock_daily_bar
  保存不复权 OHLCV

market_stock_adjust_factor
  保存 qfq_factor / hfq_factor

前端查询时：
  根据 adjust_type 动态计算价格
```

不要再保存：

```text
qfq_open
qfq_high
qfq_low
qfq_close

hfq_open
hfq_high
hfq_low
hfq_close
```

这样可以避免数据膨胀。

# 4. 数据库表设计

## 4.1 不复权日线表

你已有的话可以继续沿用。建议结构大致是：

```sql
CREATE TABLE IF NOT EXISTS market_stock_daily_bar (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    symbol TEXT NOT NULL,              -- 000002.SZ
    trade_date TEXT NOT NULL,          -- 2023-08-25

    open REAL,
    high REAL,
    low REAL,
    close REAL,

    volume REAL,
    amount REAL,
    amplitude REAL,
    pct_change REAL,
    change_amount REAL,
    turnover_rate REAL,

    data_source TEXT DEFAULT 'akshare',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT,

    UNIQUE(symbol, trade_date)
);

CREATE INDEX IF NOT EXISTS idx_market_stock_daily_bar_symbol_date
ON market_stock_daily_bar(symbol, trade_date);
```

这里永远只保存：

```text
adjust = ""
```

也就是不复权价格。

---

## 4.2 复权因子表

推荐单独建表：

```sql
CREATE TABLE IF NOT EXISTS market_stock_adjust_factor (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    symbol TEXT NOT NULL,              -- 000002.SZ
    effective_date TEXT NOT NULL,      -- 2023-08-25

    qfq_factor REAL,                   -- 前复权因子
    hfq_factor REAL,                   -- 后复权因子

    data_source TEXT DEFAULT 'akshare_sina',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT,

    UNIQUE(symbol, effective_date)
);

CREATE INDEX IF NOT EXISTS idx_stock_adjust_factor_symbol_date
ON market_stock_adjust_factor(symbol, effective_date);
```

这样每只股票只存少量复权事件，不会像日线一样膨胀。

---

## 5. 计算公式

结合 AKShare A 股因子的常见口径，可以这样处理：

```text
前复权 open  = 不复权 open  / qfq_factor
前复权 high  = 不复权 high  / qfq_factor
前复权 low   = 不复权 low   / qfq_factor
前复权 close = 不复权 close / qfq_factor
```

```text
后复权 open  = 不复权 open  * hfq_factor
后复权 high  = 不复权 high  * hfq_factor
后复权 low   = 不复权 low   * hfq_factor
后复权 close = 不复权 close * hfq_factor
```

注意：

```text
成交量、成交额、换手率一般不要用价格复权因子调整。
```

也就是说，只调整：

```text
open
high
low
close
```

不调整：

```text
volume
amount
turnover_rate
```

## 6. 查询时怎么匹配因子？

核心逻辑是：

```text
对每个 trade_date，找 effective_date <= trade_date 的最近一条因子。
```

SQLite 查询可以这样写。

### 6.1 查询前复权价格

```sql
SELECT
    d.symbol,
    d.trade_date,

    d.open  / COALESCE(f.qfq_factor, 1) AS open,
    d.high  / COALESCE(f.qfq_factor, 1) AS high,
    d.low   / COALESCE(f.qfq_factor, 1) AS low,
    d.close / COALESCE(f.qfq_factor, 1) AS close,

    d.volume,
    d.amount,
    d.turnover_rate
FROM market_stock_daily_bar d
LEFT JOIN market_stock_adjust_factor f
  ON f.symbol = d.symbol
 AND f.effective_date = (
      SELECT MAX(f2.effective_date)
      FROM market_stock_adjust_factor f2
      WHERE f2.symbol = d.symbol
        AND f2.effective_date <= d.trade_date
 )
WHERE d.symbol = '000002.SZ'
  AND d.trade_date BETWEEN '2022-01-01' AND '2023-12-31'
ORDER BY d.trade_date;
```

---

### 6.2 查询后复权价格

```sql
SELECT
    d.symbol,
    d.trade_date,

    d.open  * COALESCE(f.hfq_factor, 1) AS open,
    d.high  * COALESCE(f.hfq_factor, 1) AS high,
    d.low   * COALESCE(f.hfq_factor, 1) AS low,
    d.close * COALESCE(f.hfq_factor, 1) AS close,

    d.volume,
    d.amount,
    d.turnover_rate
FROM market_stock_daily_bar d
LEFT JOIN market_stock_adjust_factor f
  ON f.symbol = d.symbol
 AND f.effective_date = (
      SELECT MAX(f2.effective_date)
      FROM market_stock_adjust_factor f2
      WHERE f2.symbol = d.symbol
        AND f2.effective_date <= d.trade_date
 )
WHERE d.symbol = '000002.SZ'
  AND d.trade_date BETWEEN '2022-01-01' AND '2023-12-31'
ORDER BY d.trade_date;
```

## 7. 但要注意一个关键问题

AKShare 文档里也提示：`stock_zh_a_daily` 是新浪源，多次获取容易封禁 IP，并且文档建议切换为 `stock_zh_a_hist`，因为后者数据质量高、访问无限制。([AKShare][1])

所以工程上要注意：

```text
日线行情：
  优先用 stock_zh_a_hist / 东方财富源

复权因子：
  用 stock_zh_a_daily / 新浪源补充
```

这意味着你会有一个**数据源混用问题**：

```text
不复权行情来自东方财富
复权因子来自新浪
```

大多数情况下可以接受，但如果你对精度要求很高，需要做一次校验：

```text
用本地不复权价 + 因子计算出的 qfq/hfq
对比 AKShare stock_zh_a_hist(adjust="qfq"/"hfq") 返回结果
```

如果差异很小，就可以放心使用。

## 8. 建议你的系统这样实现

### 数据存储

```text
只存两类数据：

1. market_stock_daily_bar
   不复权日线

2. market_stock_adjust_factor
   前复权因子、后复权因子
```

### 前端切换复权类型

前端传：

```text
adjust_type = none / qfq / hfq
```

后端根据参数返回不同价格：

```java
if adjust_type == none:
    返回原始 open/high/low/close

if adjust_type == qfq:
    返回 open/high/low/close / qfq_factor

if adjust_type == hfq:
    返回 open/high/low/close * hfq_factor
```

### 技术指标计算

均线、MACD、KDJ、涨跌幅等指标要基于用户选择的价格口径计算：

```text
不复权页面：基于不复权 close 计算 MA
前复权页面：基于前复权 close 计算 MA
后复权页面：基于后复权 close 计算 MA
```

不要用不复权 close 计算 MA，然后叠加到前复权 K 线上。

# 9. 我的最终建议

你的项目现在最稳的方案是：

```text
保留已有不复权日线表
新增复权因子表
前后复权价格不落库
查询时动态计算
```

也就是：

```text
不存三套行情，只存：
原始行情 + 复权因子
```

第一版可以先只拉：

```text
qfq_factor
hfq_factor
```

以后如果你发现动态计算性能不够，再加一张缓存表：

```text
market_stock_daily_bar_adjusted_cache
```

但这张表不要一开始就做，避免过早增加数据量和同步复杂度。
